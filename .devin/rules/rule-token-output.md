---
description: トークン削減。コマンドの出力とファイルの読み込みを、必要な範囲に絞る
trigger: always_on
---

コマンドを実行するときと、ファイルを読むときは、次のルールに従う。

1. ビルド、lint、テストは、`run-summary <名前> <コマンド>` で実行する(例: `run-summary test composer test`)。パイプや `&&` を使う処理は、`bash -c '...'` で包む。成功したときは、表示された要約だけを見る。失敗したときは、表示された末尾 30 行だけを読む
2. 失敗の原因が、表示された範囲で分からないときだけ、表示された `log=` のファイルを、範囲を広げて読んでよい
3. それ以外のコマンドも、出力が長くなりそうなときは、`tail -n 30` や `grep` で絞る。絞るときも終了コードを失わない(`set -o pipefail` を使うか、終了コードを別に確認する)
4. ファイルを読む前に、`wc -l` と `grep -n` で、大きさと該当の場所を調べる。読むのは、該当箇所の前後だけにする
5. ファイルの全体を読んでよいのは、200 行以下のファイルと、新規に作る、または全面的に書き換えるファイルだけ
6. 会話や PR のコメントに貼る出力は、30 行までにする
7. PR 本文の「検証結果」には、絞った要点と終了コードを書く
