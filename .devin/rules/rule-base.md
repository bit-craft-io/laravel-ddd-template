---
description: 公式優先、未確認の扱い、秘密情報の扱い
trigger: always_on
---

作業するときは、次のルールに従う。

1. 公式の手順とサンプルを優先し、独自の設計をしない
2. 公式で確認できない仕様は断定せず、「未確認」と書いて報告する
3. 認証情報(API キー、パスワード、秘密鍵、`.env` の実値)を、リポジトリ、issue、PR、ログ、プロンプトに入れない。必要なときは、人が別の手段で渡す。入れてしまった場合は、作業を止めて報告する
4. 本番環境を変える操作(データの削除、インフラの破壊的な変更を含む)は、人の確認なしに実行しない
5. 次の操作は、実行前に作業を止めて、人に確認する(PR のコメントか Slack で、対象のサービス・呼び出す回数の見込み・理由を示す)
   - 課金が発生する API の呼び出し
   - 1 回の作業で、同じ API を 20 回以上呼ぶ操作
   - サービスの利用規約が禁じる、または制限する操作(スクレイピング、レート制限の回避など)
   なお、パッケージの取得、`git clone`、`docker pull`、GitHub の通常の操作は、確認なしで行ってよい
