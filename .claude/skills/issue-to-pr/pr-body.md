# PR 本文の書き方

PR を作成するときは、本文に次の項目を入れる。

1. 先頭に `Closes #<issue番号>`
2. 完了条件をチェックボックスで写し、それぞれに根拠を添える
3. 検証手順の実行結果。実行したコマンドを、省略せずに、打った形のまま、1 つずつ書く。コマンドごとに、出力(長いときは要点)と終了コードを添える。実行していない手順は「未実行」と書き、理由を添える。検証は表にする。列は「手順」「内容」「コマンド」「結果」。「内容」には、そのコマンドで何をするかを 1 行で書く
4. 表のコマンドは、そのまま貼って実行できる形で書く。複数のコマンドは `&&` でつなぎ、`/` や `→` で並べない。値を入れる部分は `<...>` で示し、何を入れるかを「内容」に書く
5. 検証を複数の環境(この環境、人の手元など)で行ったときは、環境ごとに表を分け、見出しに環境名を書く。人が実行した結果は、そのコメントへのリンクを付け、結果の値は人の出力をそのまま使う(他の環境の値を写さない)
6. 完了条件に「確認は人が行う」とあるものは、人が「確認済み」とコメントで明言したときだけ、チェックを入れ、「逸脱」の該当の行を消し、根拠を更新する。確認の結果が NG のとき、一部だけのとき、確認済みかどうか読み取れないときは、チェックを入れず、人に確認する
7. 逸脱(なければ「なし」)

例:

```markdown
Closes #5

## 完了条件
- [x] `bash scripts/hello.sh` の出力が test の1行のみ(実行結果: `test`)
- [x] 終了コードが 0(実行結果: 0)

## 検証
### Linux(この環境)
| 手順 | 内容 | コマンド | 結果 |
|---|---|---|---|
| 1 | スクリプトを実行し、終了コードを確認する | `bash scripts/hello.sh; echo $?` | 出力 `test`、終了コード `0` |
| 2 | ヘルプを表示する | `bash scripts/hello.sh --help` | 未実行(オプションがないため) |

### WSL2(人が手元で実行。[コメント](https://github.com/<owner>/<repo>/pull/<番号>#issuecomment-<ID>))
| 手順 | 内容 | コマンド | 結果 |
|---|---|---|---|
| 1 | スクリプトを実行し、終了コードを確認する | `bash scripts/hello.sh; echo $?` | 出力 `test`、終了コード `0` |

## 逸脱
なし
```
